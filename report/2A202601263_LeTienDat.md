## 4. Giải thích phần kỹ thuật đã thực hiện

### Vấn đề cần giải quyết

Đảm bảo dữ liệu clean trở thành document Chroma có metadata đủ để semantic search, exact lookup và trả lời factual có thể chấm điểm.

### Cách triển khai

`LocalEmbeddingIndex.build()` chuyển mỗi row clean thành document có `record_id`, `paper_id`, title, content và metadata. Content là `text_for_embedding`; MiniLM tạo embeddings; Chroma dùng khoảng cách cosine. Index được tách collection theo baseline/corrupted/repaired để không ghi đè trạng thái khi so sánh. `lookup()` hỗ trợ ID hoặc exact title; `answer_question()` ưu tiên title nằm trong dấu nháy đơn rồi trả lời từ metadata của top result.

### Input, output và contract

| Thành phần | Mô tả |
| --- | --- |
| Input | Clean DataFrame có `paper_id`, title, `text_for_embedding`, authors/categories joined, summary, published, URLs |
| Output | Chroma persist ở `data/chroma/`; manifests `data/embeddings/papers_embeddings*.json` |
| Module phụ thuộc | `ingestion.cleaning`, `core.config`, `sentence-transformers`, `chromadb` |
| Module sử dụng output | `retrieval.qa`, `retrieval.agent`, `evaluation.metrics`, pipelines |
| Điều kiện lỗi cần xử lý | Thiếu cột metadata, collection cũ, empty documents, model chưa tải được |

### Cách xác minh

```bash
python script/run_phase1.py
```

Sau đó chạy smoke query, ví dụ: `Who authored '<exact title>'?`, `When was '<exact title>' published?`, `What categories does '<exact title>' have?`.

- **Kết quả mong đợi:** có manifest, search trả `paper_id`/score và lookup exact title trả document.
- **Kết quả thực tế:** build index từ 24 baseline rows, 19 corrupted rows và 24 repaired rows; QA evaluation tạo answers artifact cho mỗi state.
- **Artifact/log:** ba embedding manifests trong `data/embeddings/`, Chroma persist tại `data/chroma/`, answers JSON trong `data/results/`.

## 5. Một quyết định kỹ thuật quan trọng

- **Bối cảnh:** cần so sánh ba trạng thái dữ liệu mà không để index sau ghi đè index trước.
- **Các phương án đã cân nhắc:** một collection duy nhất; ba collection riêng theo trạng thái.
- **Phương án đã chọn:** `papers-baseline`, `papers-corrupted`, `papers-repaired`.
- **Lý do:** mỗi evaluation có manifest/index độc lập, có thể audit và load lại chính xác trạng thái.
- **Bằng chứng quyết định phù hợp:** `_derive_collection_name()` map ba embedding paths vào đúng ba collection names.

## 6. Một lỗi hoặc blocker đã xử lý

- **Triệu chứng/lỗi nguyên văn:** `HTTPSConnectionPool(host='huggingface.co', port=443) ... [WinError 10013]` khi chạy trong network sandbox.
- **Lệnh hoặc bước tái hiện:** `python script/run_corruption_flow.py` trong sandbox không có quyền mạng.
- **Nguyên nhân gốc:** sentence-transformers kiểm tra model hub khi khởi tạo model; sandbox chặn socket ra ngoài.
- **Cách xử lý:** cài dependency và chạy pipeline với quyền mạng; model MiniLM được cache sau lần chạy đầu.
- **Cách xác minh sau khi sửa:** build ba collections và lưu ba manifests; comparison metrics chứng minh repaired index trả baseline performance.
- **Điều học được:** retrieval contract phụ thuộc trực tiếp vào schema và môi trường model; thiếu metadata hoặc model cache đều có thể chặn QA factual.

## 7. Hiểu biết về luồng end-to-end

Crossref được clean thành document text và metadata, rồi MiniLM biểu diễn document/query thành vector để Chroma tìm top-k. Evaluation so retrieved IDs với `ground_truth_doc_ids` từ clean data, sau đó chấm answer. Quality đánh giá tính đúng/đủ của row, freshness đánh giá tuổi dữ liệu. Cùng test set giúp chênh lệch retrieval phản ánh index/corpus khác nhau. Repair dựng lại corpus/index từ raw và cần được xác nhận qua manifest, quality reports và metrics.

## 8. Phân tích kết quả

| Metric/signal | Baseline | Corrupted | Repaired | Nhận xét của cá nhân |
| --- | ---: | ---: | ---: | --- |
| `retrieval_hit_rate` | 1.000 | 0.250 | 1.000 | Top-k mất six ground-truth documents đã bị drop. |
| `mean_token_f1` | 1.000 | 0.408 | 1.000 | Factual extraction phụ thuộc top result/corpus. |
| `judge_accuracy` | 1.000 | 0.375 | 1.000 | Answers artifact xác nhận recovery. |
| `mean_judge_score` | 5.000 | 2.625 | 5.000 | Repaired collection đạt baseline theo Gemini judge. |
| Ragas: precision/recall/faithfulness | 0.750/0.750/0.750 | 0.125/0.125/0.286 | 0.750/0.750/0.750 | Chroma corpus repaired phục hồi grounding. |
| Quality checks | PASS | FAIL | PASS | Corpus corrupted có duplicate/blank content. |
| Freshness status | Fresh | Stale | Fresh | Một document bị đặt date cũ. |

Metrics xác nhận corrupted index thực sự khác baseline: hit rate giảm từ 1.000 xuống 0.250. Repaired manifest/collection được build lại từ raw-clean DataFrame và trả về toàn bộ metrics 1.000/5.000; điều này loại trừ việc vô tình đánh giá lại baseline index.

## 9. Điều học được và hướng cải thiện

1. Embedding index cần manifest để tái hiện collection/document state.
2. Exact lookup theo title/ID bổ sung cho semantic search khi câu hỏi factual.
3. Tách collection theo trạng thái là điều kiện để so sánh công bằng.

Nếu có thêm thời gian, thêm automated smoke tests cho build/search/lookup với một DataFrame fixture nhỏ.
